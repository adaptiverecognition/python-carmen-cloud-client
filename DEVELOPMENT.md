# Development

## Setup

```bash
python -m venv .venv && . .venv/bin/activate
pip install -e ".[dev]"
cp .env.example .env   # optional: API keys for the live API tests
pytest
```

Tests that call a live recognition API are skipped unless `TEST_DEV_API_KEY` is
set. The Carmen Cloud API tests mock HTTP with `responses` and always run.

## Updating the API models

All models are generated by `./generate-response.sh` (datamodel-code-generator,
pydantic 2) from the files in `assets/`:

- **Vehicle / Transportation & Cargo API**: `assets/{vehicle,transport}/response.schema.json`,
  the API Gateway response models (`aws apigateway get-model --rest-api-id <id> --model-name Response`).
- **Carmen Cloud API and Authentication**: `assets/carmen-cloud/*.json`, OpenAPI
  documents built from the API documentation specs in `carmen-cloud-cdk` (the
  same specs CDK publishes to API Gateway):

  ```bash
  cd ../../carmen-cloud-cdk
  TS_NODE_TRANSPILE_ONLY=1 node -r ts-node/register \
    ../libraries/python-carmen-cloud-client/scripts/openapi/dump-cdk-api-docs.ts "$PWD" /tmp/specs.json
  cd -
  python3 scripts/openapi/build_openapi.py /tmp/specs.json assets/carmen-cloud
  ./generate-response.sh
  ```

  Only the bearer-token routes are included; the console-only SigV4 routes
  (workspace list/create, invitations) are not part of the API-key surface.
  The JS client (`js-carmen-cloud-client`) uses the same scripts and documents.

## Releasing

1. Bump `version` in `pyproject.toml` and `__version__` in `carmen_cloud_client/__init__.py`.
2. Commit, then tag and push: `git tag v2.0.0 && git push origin master v2.0.0`.
3. `.github/workflows/release.yml` builds the package and publishes it to PyPI
   with trusted publishing (OIDC). No PyPI token is stored anywhere; the trusted
   publisher is configured once in the project settings on pypi.org.
